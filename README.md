# AI Support Ticket Analyzer

An LLM-powered support ticket analysis system built with Python, Pydantic, and Qwen3:8B.

The application processes customer support messages and automatically extracts structured information, including ticket category, priority, sentiment, and recommended actions. It uses locally hosted LLM inference through Ollama and Pydantic for structured output validation.

## Features

- **Ticket Classification:** Categorizes messages into billing, technical, account, and general.
- **Priority Detection:** Assigns low, medium, or high priority based on the issue.
- **Sentiment Analysis:** Identifies positive, neutral, frustrated, and angry customer sentiment.
- **Automatic Summarization:** Generates concise summaries of customer complaints.
- **Human Escalation:** Determines whether a ticket requires human intervention.
- **Suggested Actions:** Recommends appropriate next steps for support teams.
- **Structured Outputs:** Uses Pydantic and JSON Schema to enforce consistent response formats.
- **Local LLM Inference:** Runs Qwen3:8B locally through Ollama.

## Getting Started

### Prerequisites

- Python 3.10+
- [uv](https://docs.astral.sh/uv/)
- [Ollama](https://ollama.com/)

### 1. Clone the repository

```bash
git clone <your-repository-url>
cd ticket-analyzer
```

### 2. Install the model

Download Qwen3:8B using Ollama:

```bash
ollama pull qwen3:8b
```

Ensure the Ollama service is running before executing the application.

### 3. Install dependencies

This project uses `uv` for dependency management.

```bash
uv sync
```

### 4. Run the application

```bash
uv run main.py
```

### 5. Run evaluation

Execute the evaluation script to compare model predictions against predefined expected classifications.

```bash
uv run evaluate.py
```

## Example

### Input

```text
I've been charged twice for my subscription,
and nobody from support is responding.
I need my money back immediately!
```

### Output

```json
{
  "category": "billing",
  "priority": "medium",
  "sentiment": "angry",
  "summary": "Customer was charged twice for their subscription and is requesting a refund.",
  "requires_human": true,
  "suggested_action": "Escalate the issue to the billing support team and investigate the duplicate charge."
}
```

*Note: Actual classifications and suggested actions are generated by the model and may vary.*

## Evaluation

The application includes an evaluation script that compares model predictions against manually defined expected labels.

Initial and improved evaluation results:

| Metric | Initial | Improved |
|---|---:|---:|
| Category Accuracy | 80% | 100% |
| Priority Accuracy | 60% | 80% |

The improved results were achieved through prompt refinement and temperature configuration.

Evaluation was conducted using a small dataset of five test cases. These results are indicative and should not be interpreted as production-level performance benchmarks.

## Limitations

- Classification accuracy depends on model behaviour and prompt quality.
- Priority assignment can be subjective and context-dependent.
- Evaluation currently uses a small manually labelled dataset.
- Structured outputs ensure format validation, not semantic correctness.
- The application does not integrate with external customer support or billing systems.
